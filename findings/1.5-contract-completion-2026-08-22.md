## Blocking

- **CC-A-001 — the frozen `SignalState` projection gives no responsiveness credit to the
  successful clear-before-fire path.** The projection requires both timestamps and computes
  `acted_before_fire = cleared_round is not None and fire_round is not None and
  cleared_round <= fire_round` (`contract-spec.md:158-161`, duplicated in
  `CONTRACTS.md:421-425`). But the same candidate requires clearing `wh_rollout_01` to prevent
  `warehouse_rollout_gap` from firing (`contract-spec.md:299-303`), so the successful path
  has `cleared_round != None` and `fire_round == None` and projects to **False**. That is the
  opposite of the 1.4 scorer's numerator, which counts `SignalState.acted_before_fire`
  (`backend/app/engine/management.py:138-143`), and it cannot reproduce the seeded
  `ord_cap_01(... acted_before_fire=True)` without inventing a fire timestamp
  (`backend/seeds/riverside_r3.py:193-198`). Freeze one total rule for a timely clearing action
  that prevents firing, then show the three-row projection arithmetic explicitly.

- **CC-A-002 — action history, clearing scope, and affordability remain undefined.** The
  original dispatch requires action type, locked round, capability/target scope, and cost;
  the candidate adds only `available_funds_by_round` and no action-history object
  (`contract-spec.md:163-172,267-277`; current `DecisionState` has only category, capability,
  capex and RGT fields at `backend/app/engine/state.py:112-125`). Consequently the engine
  still cannot decide which committed action clears which signal. The price lookup is also
  not executable as written: `add_training` takes the minimum of all training options, but
  Riverside deliberately authors a `none` option with cost 0 and coverage 0
  (`backend/packs/riverside_grocery/catalog.yaml:58,80`), so the cheapest candidate need not
  perform the clearing action. `available_funds` is described only as coming from either
  authored `budget.capex_per_round` or future 1.6 state (`contract-spec.md:170`), without
  deciding whether committed spend has already been deducted. Define the immutable action
  and funds history, exact target matching, effectful-option filtering, and round-by-round
  affordability derivation.

- **CC-A-003 — `policy_contradiction` divides by zero for valid casepacks.** The exact test
  divides each option index by `n = len(options) - 1` (`contract-spec.md:195-199`). Existing
  schema permits both the legacy zero-option shape and a one-option policy; the permanent
  contract check explicitly proves zero-option policies load
  (`backend/tests/check_policy_options.py`, “legacy PolicyOption … options==[]”). A
  one-option policy with a valid default resolves but yields `0 / 0`; a zero-option policy
  has no index at all. The table's generic “unresolved raises” text does not settle either
  valid shape. Define zero/one-option semantics and add those boundary cases to the required
  tests before this formula is dispatchable.

- **CC-A-004 — event ownership is not total or deterministic, so O2 and blast-radius binding
  remain undefined.** Capability attribution is a set and permits empty or multi-capability
  results (`contract-spec.md:210-211`), but the suppression record contains one singular
  `capability` (`:217-218`) without defining which capability is recorded if several caps are
  exhausted. More seriously, blast-radius fallback selects the bottleneck of “the primary
  capability” (`:234-242`), but no primary capability is defined for an empty or multi-cap
  event. Python set iteration cannot supply the promised deterministic authored order. Freeze
  an ordered attribution, cap-consumption/suppression rule for multi-cap events, the empty-set
  path, and a total failed-node binding.

- **CC-A-005 — the schema gate contradicts the claimed dispatchable scope.** The live 1.5
  spec says all five metric functions must exist before the deck is executable
  (`handoffs/1.5-event-signal-engine/spec.md:107-110`). `availability_shortfall` requires the
  new `Capability.agreed_availability` field (`contract-spec.md:119-128`), yet pre-flight row
  7 authorizes that path to remain deferred when the field is absent (`:332-343`), and §9
  simultaneously says the core proceeds while availability waits (`:274-281`). A builder
  therefore cannot both implement all five required metrics and obey the sequencing STOP.
  Either land the owned 1.1/1.2 schema prerequisite before dispatch, or explicitly redefine
  the build boundary and all-five acceptance rule through the proper authority.

- **CC-A-006 — the §11 falsification register does not cover the material invariants and one
  listed canary cannot detect what it claims.** CC8 claims to guard identity branching, I/O,
  clock, and randomness but its grep matches only `riverside|grocer|random.|datetime.now`;
  planting `open(...)` or a session access passes it (`contract-spec.md:308-319`). There are
  no planted-defect checks for recurrence/immutability, lifecycle status ordering,
  action-target matching and price selection, the eleven promised precondition boundaries,
  multi-cap suppression ordering, failed-node binding, or duration evidence. The table says
  “each shown to fail,” but no executable evidence exists for those claims. This fails
  `SPEC_PROTOCOL §4.3/§11`; replace the ritual grep and derive falsification rows from every
  load-bearing contract before dispatch.
