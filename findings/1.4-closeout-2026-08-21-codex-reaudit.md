## 1.4-CR-001 — required unknown-archetype failure was replaced with an exclusion

**Severity:** Contract / Functional  
**Location:** `backend/app/engine/management.py`, `policy_switch_alignment()`  
**Builder disclosure:** `handoffs/1.4-scoring-engine/closeout.md`, deviation D3

Closeout decision 9 requires an unknown stakeholder archetype to raise `ValueError` before
a score is returned. The implementation performs:

```python
arow = pref_domain.defaults_by_archetype.get(sh.archetype)
if not arow:
    continue
```

Thus an archetype absent from the policy preference table is excluded, whether it is a
legitimate archetype with no policy view or a malformed/unknown archetype. The builder and
prior auditor correctly identified an internal tension: decision 3 requires archetypes with
no policy row to be excluded, while the present model has no independent archetype registry
with which to distinguish “known but uninterested” from “unknown.”

That tension does **not** authorize choosing one rule. Closeout decision 4 explicitly says
to STOP when the current models cannot express the verified rule. Under the platform’s
no-assumption protocol, the previous audit’s acceptance cannot substitute for a resolved
contract.

### Required resolution

The spec owner/coordinator must choose and record one verified contract before code changes:

1. define a canonical archetype vocabulary/registry and raise only when the stakeholder’s
   archetype is absent from it, while continuing to exclude known archetypes with no policy
   preference; or
2. explicitly remove the unknown-archetype failure requirement because pack validation or
   another named contract guarantees stakeholder archetype validity upstream.

The builder must then add the corresponding regression test. Do not infer the choice.

## 1.4-CR-002 — policy-domain overrides are exposed but silently ignored

**Severity:** Contract / Functional  
**Location:** `backend/app/engine/management.py`, `policy_switch_alignment()`  
**Builder disclosure:** `handoffs/1.4-scoring-engine/closeout.md`, deviation D4

Closeout decision 4 says stakeholder overrides replace the corresponding archetype decision
row if the loader exposes them; if the current models cannot express that verified rule, the
builder must STOP rather than invent a resolver. `PreferenceDefaults` does expose
`overrides` as `list[dict[str, Any]]`, but no policy-domain override schema is defined.

The implementation reads only `defaults_by_archetype` and never inspects `overrides`.
Riverside happens to declare `overrides: []`, so the current seed score is unaffected, but a
future or mutated validly-loaded pack with non-empty policy overrides would be scored as if
the overrides did not exist. That is precisely the silent path decision 4 prohibited.

### Required resolution

Before merge, choose and record one evidence-backed contract:

1. define and validate the policy override shape, implement replacement semantics, and add
   precedence/non-duplication tests; or
2. explicitly declare policy-domain overrides unsupported for this closeout and fail loudly
   when `pref_domain.overrides` is non-empty, with a focused negative test and a named future
   owner for defining the shape.

Given that no current policy pack uses overrides, option 2 is the smallest compliant
closeout, but the choice belongs to the spec owner/coordinator—not the builder or auditor.
