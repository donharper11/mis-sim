## Report

  §5.4 states the v1.0 projection rule "drives the pin to 0.0 / `make check` FAILS." I planted the
  v1.0 rule (`fire_round is not None` required) in `ledger.py:project_signal_state`: the literal pin

  `seeds/riverside_r3.py:196-198`, not the projection), while `test_cc4_projection_reproduces_seed_rows`
  **failed**. So `make check` does fail on the defect — but via the CC4 projection-reproduces-seed
  assertion, not a drift in the pin test itself. The protection is real and the guard is not a ritual;
  only the "the pin drifts" phrasing is loose. The actual seam is CC4 keeping the projection and the
  hand-built seed rows in lockstep.

- 1.5-ENG-003 (Report): Contract-spec §5.5.4's worked example states `wh_rollout_01`'s cheapest
  effectful fix = `12000` (add_training basic). The engine computes **3000**
  (`cheapest_effectful_fix` verified directly), because `wh_rollout_01.cleared_by` is
  `[add_training, redesign_process, fund_response]` — the illustrative example considered only
  add_training and understated the `cleared_by` set. The **build is correct**: the seed's authored
  `cheapest_fix_when_raised=3000` (`seeds/riverside_signals.py:51`) matches the engine's own
  computation. Since the contract-spec explicitly flags all fix figures as illustrative/1.7
  calibration (§0.5 S1), this is a stale figure in the spec prose, not a build defect.
