## Findings

### Functional

**0.2-001 — `react-router-dom` ships a known high-severity advisory; a non-breaking fix
exists and was not applied.**

The DoD records "8 high vulnerabilities" as a single undifferentiated number. They are not
equivalent:

```
~6 of 8   brace-expansion → minimatch → eslint / eslint-plugin-react
          DEV-ONLY. Not shipped to the browser. Fix requires eslint@10 (breaking).
          Deferring is correct.

  2 of 8  react-router 7.12.0–8.2.0 → react-router-dom     GHSA-qwww-vcr4-c8h2
          RUNTIME DEPENDENCY. Shipped. `npm audit fix` is NON-BREAKING.
```

Real exploitability is low — the advisory is RSC-mode specific and this is a plain Vite
SPA — so this is not blocking. But a free fix on a shipped dependency should be taken
rather than logged. **Action:** `npm audit fix`, re-commit `package-lock.json`, and split
the two classes in the DoD note.

### UX / Design

**0.2-002 — `--color-primary-hover` is not a hue-consistent hover for `--color-primary`.**

Visible in `screenshots/0.2/tokens-1280.png`:

```
  --color-primary        #1E40AF   blue
  --color-primary-hover  #1E293B   slate   ← different hue family
```

globalstrat's original pairing was `#2563EB` → `#1D4ED8` — same hue, darker. The
re-point to BECSR values mapped `hover` onto `--bg-sidebar-active`, which is a surface
colour, not a darker primary. A button that shifts blue → slate on hover reads as broken.

**Action:** set `--color-primary-hover` to a darker shade of `#1E40AF` (e.g. `#1E3A8A`).
Mechanical re-pointing across two token systems needs a semantic-relationship pass, not
just a value swap.

### Design debt — input to module 0.6, not a 0.2 defect

**0.2-003 — 89 tokens with heavy aliasing and no usage guidance.**

Merging BECSR names with globalstrat names produced multiple names per value. `#1E40AF`
alone is reachable through **seven**: `--accent-navy`, `--text-link`, `--brand-primary`,
`--color-header-financial`, `--color-primary`, `--color-input-focus`, `--color-text-link`.
`--bg-sidebar` and `--color-surface-900` are both `#0F1724`.

The spec asked for exactly this merge, so the builder complied. But when 0.6 builds
`PanelCard` and `MetricCard`, nothing says which name to reference — and two components
picking different aliases for the same value is precisely the drift a design system exists
to prevent.

**Action for 0.6's spec (mine to write):** declare one canonical name per semantic role
and mark the rest as deprecated aliases, or collapse them. Do not leave the choice to
component authors.

### Report accuracy

**0.2-004 — the `typecheck` script does not type-check.**

`"typecheck": "vite build --mode typecheck"` on a project with zero TypeScript files is a
second build. The DoD's "npm run typecheck exited 0" is true but conveys nothing.
**Action:** remove the script, or rename it. Ladder rung 2's typecheck is legitimately
N/A for a JSX project — say that instead.

### Watch item — no action

**0.2-005 —** Slow-3G render of `/_dev/tokens` exceeded 60s (builder-reported). Acceptable
for an 89-swatch developer page that ships to no student. Noted only so it is not mistaken
for a baseline if a product screen later shows similar numbers.
