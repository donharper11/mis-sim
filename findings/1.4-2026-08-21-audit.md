## Data
- **1.4-001: spec §5.3 says `strategic_alignment` is a "dot product"; the engine implements
  cosine similarity.** `management.py:57-71` (`_cosine`). A literal dot product of dollar
  spend × weights would not sit in `[0,1]` and would be meaningless inside a `geomean`, so
  cosine is the correct engineering choice and it reproduces the approved Mgmt pin. The DoD
  discloses it (§5 §C: "cosine …"), so this is *disclosed*, not silent. Per GOVERNANCE §7 a
  spec/code wording divergence is still a finding: recommend the author bless "cosine" in
  spec §5.3 so the contract text matches the code.
- **1.4-002: design/02 §A "Data currency / freshness" (the platform data-platform setting)
  is not a distinct sub-factor.** Only component currency (`1 − age/service_life`,
  `technology._currency`) is implemented; the DoD §A folds the two currency rows into one.
  Defensible (freshness is a platform-setting/round-evolution concern nearer 1.6), but the
  fold is not called out as a deferral in the DoD's §A table — confirm it is intended.

## Report
- **1.4-003: pre-flight row 4 target string is absent from the 0.3 spec (confirms DoD F-1).**
  `grep "0.75 · Org 0.51 · Mgmt 0.65" handoffs/0.3-mockup-pilot/spec.md` → not found. The
  arithmetic target itself is intact and approved in this spec §5.6/§5.7. Repoint the

- **1.4-004: adoption is consumed as a state input; spec §5.2's "formula in §5.6" does not
  exist (confirms DoD F-2).** §5.6 states no adoption formula and the 1.1 schema carries no
  adoption params. `organisation.py:65` reads `DeploymentState.adoption` directly. Deferring
  the simulation formula to 1.6 is reasonable and disclosed; if 1.4 is meant to *own* the
  formula, that needs a casepack schema change and a calibration pass — author to confirm.
- **1.4-005: the CLI lives inside the engine package.** `score.py:_main` calls `print`,
  `json.dumps`, and dynamically imports `app.seed.demo.load_scenario` — i.e. the
  `app/engine` package performs I/O when run as `__main__`. The scoring *functions*
  (`score_team`/`score_capability`) are pure and the I2 grep passes, so this is not an I2
  violation as specified, but "the engine package does no I/O" would be true by construction
  if the CLI wrapper moved to `app/seed` or a `scripts/` module. Optional hardening.
- **1.4-006 (note, no action): realised 0.246 vs the spec example 0.249** is a display-
  rounding artefact of the spec's own worked example, inside tolerance; `firm_score` is
  0.2493. Recorded so the next reader is not surprised by the two-vs-three-decimal gap.
