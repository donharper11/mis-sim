### B4 · The six vocabularies — permissive at index 0, and genuine scales

```
data_collection    everything_by_default → purpose_limited  → minimal              monotone: scope ↓
data_retention     indefinite            → standard_period  → minimal              monotone: duration ↓
data_access        open_to_all_staff     → role_based       → need_to_know         monotone: audience ↓
```

**All six are ordered scales, not three unrelated labels.** Each middle value is genuinely between

**Index 0 is the permissive value on all six**, and it is the value `obligation_rules.yaml` names
in all six (table in A3). **Consistent, per §3.5b.**

Two of the eighteen values are nobody's ideal — `1.3-f-006`.

## Part D — the design ambiguity, and the author's ruling

### D1 · Was the builder right to report rather than decide? **Yes. Unambiguously.**

`design/07 §3.5` (as it then stood) said `employees` want **strict** on `staff_monitoring`. In the
pack's vocabulary the permissive value of that switch is `untracked`, so "strict" reads as *more
surveillance* — the document, read literally, said employees want to be watched more.

Deciding that on the merits would have required the sim to hold a position on whether workplace
monitoring is good, which `GOVERNANCE §4.7` and the instruction's own closing line
(*"that would be the sim taking a stance, and it is the one thing this packet must not do"*)
forbid outright. The builder instead:

1. followed `design/07`'s own **reason** column — *"being watched is not free"* — which is an
   interest, and interests are what the file records;
2. authored `untracked` for authoring purposes only;
3. wrote the conflict up at length in `dod-followup.md §11`, flagged it as *"the one item a fresh
   auditor should look at first"*, and stated that rewording `design/07` **is an AUTHOR decision**;
4. **edited no design document.** `git diff` confirms: `design/` is untouched on this branch.

That is `GOVERNANCE §4.4` — *a builder that encounters an unspecified case stops and reports; it
does not improvise, and it does not resolve a spec/code conflict on its own authority* — executed
exactly as written. The author then ruled in §3.5a. **The process worked. Record it as the
reference example.**
