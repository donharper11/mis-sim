### 1.2-020 — `E13` resolves `unit_responses[].contributing` against a vocabulary derived from the pack's own capabilities, so a legitimate Porter value-chain activity raises a false ERROR — BUILD

`validate.py:891` resolves `contributing` against `lens.chain_positions | lens.capability_keys`,
where `chain_positions` (`validate.py:427`) is built **from the pack's own capabilities**:

```
$ sed -n '885,897p' backend/app/casepack/validate.py
    for unit in state.unit_responses:
        ...
        # `contributing` names a value chain activity; a capability IS one (1.1 O1), so
        # either vocabulary resolves it.
        if unit.contributing not in lens.chain_positions | lens.capability_keys:
```

A pack whose capabilities happen not to occupy an activity therefore cannot say that a unit
contributes to it. Demonstrated on a copy of `minimal_valid` with **one** field changed, from
`service` to `procurement` — one of Porter's nine, and a value Riverside itself uses
(`pack.yaml:64`, `procurement: 0/3`):

```
$ cp -r backend/tests/fixtures/packs/minimal_valid <scratch>/probe_chain
$ (pack.yaml:53   contributing: service  ->  contributing: procurement)
$ ./backend/bin/validate_casepack <scratch>/probe_chain

  ERROR  E13  Opening position                pack.yaml:53
         The opening position names the capability 'procurement', which this company does not have.
         Fix: in pack.yaml, name a capability the pack declares, or remove the reference from initial_state.
         Field: initial_state.unit_responses.clinical_team.contributing

  1 error · 0 warnings · exit 1
EXIT=1
```

Two defects in one line. The content is correct and is reported as an error; and the message
calls a value-chain activity a **capability**, which it is not.

This is the *same* argument the builder used to decline the `value_chain_coverage` arm
(`dod.md:745-766`), applied to one field and not to its sibling. Both fields are keyed by
activity — `mockups/dashboard.html` renders them from the same vocabulary
(*"**Contributing** Outbound logistics"*, *"Coverage across the value chain: Inbound 1/4 ·
Operations 2/4 · Outbound 4/5 …"*).

**Why it is not blocking today:** no pack in the repository triggers it. Riverside's three
`contributing` values (`outbound_logistics`, `operations`, `firm_infrastructure`) all happen to
be occupied chain positions, and `minimal_valid`'s two (`operations`, `service`) are its two
capabilities' chain positions exactly. **It becomes blocking at 1.3**, which regenerates
`initial_state`, and it is a false ERROR from the artifact `GOVERNANCE §5` uses as a gate
("No casepack reaches a section until `validate_casepack` passes clean").

**Closes when** `contributing` resolves against a closed value-chain vocabulary rather than a
pack-derived one — see `1.2-021` for where that vocabulary can be sourced.

### 1.2-022 — A pack file that exists and is valid YAML but cannot be **read** escapes `E00` and reaches the instructor as a raw Python exception at exit 2 — BUILD

`read_raw` catches `yaml.YAMLError` only:

```
$ sed -n '240,253p' backend/app/casepack/validate.py
        try:
            raw[section] = _read_yaml(path) or {}
        except yaml.YAMLError as exc:
```

`OSError` / `PermissionError` therefore propagates to `main`'s catch-all, which prints the
exception class and its message and returns 2 (`validate.py:1453-1455`):

```
$ cp -r backend/tests/fixtures/packs/minimal_valid <scratch>/p_d && chmod 000 <scratch>/p_d/labels.yaml
$ ./backend/bin/validate_casepack <scratch>/p_d
PermissionError: [Errno 13] Permission denied: '/…/scratchpad/p_d/labels.yaml'
EXIT=2
```

Three rules disagree with that output. `spec.md:151-153` defines `E00` as *"a pack file is
missing **or cannot be parsed**"* and §3 decision 8 is explicit: *"a broken pack, not a broken
validator, so it is an ERROR and exit 1, **never the exit 2 reserved for our own failure**."*
`GOVERNANCE §4.10`: *"Users may not see our errors."* And `1.2-016` item 1 ratified `E00` into
the code list precisely to avoid *"a Python traceback at an instructor."*

An unreadable file is a broken pack. It should be `E00`, exit 1.

**Not blocking** — the condition needs a filesystem permission fault, not an authoring mistake.
**Closes when** `read_raw`'s `except` also covers `OSError`.

### 1.2-029 — `REVIEW_AREAS` is a new cross-cutting vocabulary with no `CONTRACTS.md` entry. Ruling: it is **not** the same list as `decision_line.category`, and the two need a stated mapping rather than a merger — SPEC / CONTRACTS

The builder introduced `REVIEW_AREAS` (`checks.py:52`) because `rework.md §1` ruling 2 required
`review.lines[].area` to resolve to *"the seven decision areas"* and no constant named them, and
declared the open question at `dod.md:784-785`. Sourcing verified byte-for-byte against the
mockup, which is the right source — deriving it from Riverside would have put case knowledge in
the engine:

```
$ grep -o "<th>Area</th>.\{0,420\}" mockups/review.html
```
*(one long line; wrapped here for reading, and the seven `<td>` area cells are the whole point —
the row contents between them are elided with `…`, which is why this block is labelled abridged
and not verbatim)*
```
<th>Area</th><th>Changes</th><th>Capital</th><th>Run-rate effect</th></tr></thead><tbody>
<tr><td>Platform</td>… <td>Components</td>… <td>Rollout</td>… <td>Services</td>…
<td>People</td>… <td>Governance</td>… <td>Challenges</td>…
```

**Ruling: they should not be one vocabulary.** `CONTRACTS.md` § `decision_line.category` is a
**twelve**-value per-decision enum that *"portfolio discipline, the Run/Grow/Transform mix, and
the maintenance floor all aggregate on"*. `REVIEW_AREAS` is a **seven**-row screen roll-up. The
relation is many-to-one and lossy in both directions:

```
platform     <- platform_service          services   <- (no category)
components   <- application, integration, lifecycle
rollout      <- training, process_redesign, communication
people       <- staffing                  governance <- governance
challenges   <- event_response            (no area)  <- policy, capital_request
```

Two categories (`policy`, `capital_request`) have no review row at all, and `services` has no
category. Collapsing them would break the three scorers `CONTRACTS.md` warns about; leaving them
unrelated is how `0.4-001` happened. What is missing is the mapping, in the one file that exists
for exactly this — *"Add when a field is consumed in more than one place and its format could
plausibly be guessed wrong."* `review.lines[].area` is now consumed by the validator, by the 0.4
review screen, and by whatever 1.3 authors into `initial_state`.

**Not blocking. Closes when** `CONTRACTS.md` gains a `review.lines[].area` entry naming the seven
values, their source, and the roll-up from `decision_line.category`.
