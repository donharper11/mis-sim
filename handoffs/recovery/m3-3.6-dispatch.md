# M3.6 Rollout dispatch

Implement the Rollout surface against the existing P1 organisation commands and M2/M3
scope boundary. Read active catalog assets and rollout records from versioned checkpoints,
retain legacy deployment rows as a read fallback, and expose only registered training,
process, and communication options.

The frontend owns `/rollout`, the deployments table, selected deployment detail, and the
per-deployment mix. Writes must validate `SheetPatchV1` and call `SimulationService`; do
not create a second adoption or organisation state store. Locked and unavailable runtime
states remain explicit and do not become local UI fixtures.
