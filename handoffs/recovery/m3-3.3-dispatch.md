# M3.3 Dashboard dispatch

## Scope

Implement the authenticated dashboard read surface over existing persisted runtime state.

Allowed product files:

- `backend/app/api/dashboard.py`
- `backend/app/main.py`
- `backend/tests/test_dashboard_api.py`
- `frontend/src/pages/Dashboard.jsx`
- `frontend/src/pages/Shell.jsx`
- `frontend/src/components/AppShell.jsx`
- `frontend/src/styles/theme.css`
- `docs/frontend-dashboard.md`
- this dispatch and `m3-3.3-dod.md`

Do not add scoring, transition, decision mutation, or fixture data. The endpoint must preserve
instance authorization and student team isolation. The browser page must render nullable data as
an empty state or `—`, rather than claiming that a team has a result which is not persisted.

## Source contract

`RoundResult.payload` is authoritative for scorecard and signal results. Legacy runtime estate
tables are authoritative for unit response. The versioned checkpoint is a read fallback. The
dashboard is a projection only; it must not recompute scores.

## Acceptance evidence

1. Focused API test proves persisted scorecard, signal and unit rows render, and a student cannot
   read another instance or another team.
2. Frontend lint and production build pass.
3. Browser probe at 1024px with mocked authenticated API responses sees Dashboard, a scorecard
   value and attention item, with no horizontal overflow or page error.
