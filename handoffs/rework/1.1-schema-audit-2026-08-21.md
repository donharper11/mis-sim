# Rework — 1.1 Casepack Schema

Date: 2026-08-21 · Independent audit against current `main` (`174e980`)

## Verdict

REWORK REQUIRED BEFORE 1.4 MAY RELY ON POLICY DISTANCE. The model contract contradicts the
settled design and the cross-cutting contract is absent.

## Finding `1.1-RA-001` — `PolicyOption.options` declares the opposite ordering rule

Severity: Blocking for 1.4

Evidence:

```text
backend/app/casepack/models.py:438-439
Ordering is an authoring convention and carries no meaning: do not infer strictness
from position.

design/07-decision-consequence-map.md:143-145
PolicyOption.options is ordered, least constrained first
```

The active 1.4 design requires ordinal distance, so a builder cannot satisfy both sources
without silently choosing one. `GOVERNANCE.md §7` requires a stop on this conflict.

## Finding `1.1-RA-002` — no cross-cutting `PolicyOption.options` contract

Severity: Functional

`CONTRACTS.md` has no entry for `PolicyOption.options` or `PolicyOption.default`, although
the schema, harvested content, validator, scoring engine, event engine, and future UI all
consume these values. Its closest controlled-vocabulary entry,
`entity.level_of_detail`, is explicitly ordinal; leaving this one undocumented makes the
opposite interpretation plausible.

### Required rework

1. Correct `models.py` so its field documentation states the settled ordinal contract:
   index 0 is least constrained and distance is meaningful.
2. Add a versioned `CONTRACTS.md` entry naming canonical ordering, producer, consumers,
   invalid shapes, and the distinct meaning of `default` versus `permissive_value`.
3. Add schema/loader tests proving order survives YAML load and round-trip unchanged.
4. Run all 29 fixture rows and Riverside validation after the change.

### Acceptance

There is one unambiguous ordering rule in design, model documentation, authoring docs, and
`CONTRACTS.md`; fixture matrix and Riverside validator remain clean.
