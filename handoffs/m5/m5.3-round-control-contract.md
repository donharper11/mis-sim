# M5.3 round control — instructor round management contract

Date: 2026-10-02
Status: bounded implementation handoff; no runtime implementation is included here.
Scope: instructor round-control UI and pause/resume/reopen/schedule-settings surface.

## Decision

The M5.3 slice delivers **instructor round-control operations**: a frontend page
showing per-round, per-team lock/advance status with manual lock, advance, reopen,
pause/resume, and schedule-settings editing.  It consumes the existing scheduler and
round-control services and wires them to an instructor-facing UI.

This is deliberately bounded to instructor-initiated actions and schedule visibility.
It does not include scheduler tick automation, student-facing schedule display, grade
integration, or new database tables.

## Exact missing contracts

### 1. Pause and resume

New routes:

```http
POST /api/instances/{instance_id}/round-control/pause
POST /api/instances/{instance_id}/round-control/resume
```

Both require `instructor_or_ta` auth and ownership of the instance's course.

- **Pause:** sets `instance.status = 'paused'`; while paused, student `PATCH` to
  controls/sheet returns 409 with a typed `instance_paused` error.  Pausing a
  non-active instance returns 409.
- **Resume:** sets `instance.status = 'active'`; student patches succeed again.
  Resuming a non-paused instance returns 409.

The pause enforcement belongs in the simulation service patch path, not in a
middleware or decorator that would affect unrelated routes.

### 2. Manual lock

New route:

```http
POST /api/instances/{instance_id}/round-control/lock
```

Calls the existing `SimulationService.lock()` to lock all draft teams at their
current revision for the current round.  Already-locked teams are unchanged;
completed teams are skipped.  Returns the per-team lock result summary.

### 3. Manual advance

The existing `POST /instances/{id}/round-control/advance` is wired to the UI.  No
new backend route is needed; the frontend calls the existing endpoint.

### 4. Reopen

New route:

```http
POST /api/instances/{instance_id}/round-control/reopen
```

Accepts a `team_id` in the request body.  Calls the existing
`SimulationService.reopen()` for the specified team.  The team must be locked but
not advanced.  Returns the team's updated state with incremented revision.  Other
teams are unaffected.

### 5. Schedule read

New route:

```http
GET /api/instances/{instance_id}/round-control/schedule
```

Returns per-round schedule data: `start_at`, `deadline`, `decisions_locked`, and
per-team `locked_at`/`advanced_at` timestamps.  Instructor/TA auth required.

### 6. Round schedule settings editor

New route:

```http
PATCH /api/instances/{instance_id}/settings
```

Accepts updates to `default_round_duration_hours`, `auto_advance_on_deadline`,
`grace_period_minutes`, and `lock_warning_minutes`.  Persists into
`instance.settings` JSON.  Values are validated (positive durations, boolean
auto-advance).  Next round schedule reflects updated values.

## Narrow packet boundary

### In scope

* Instructor round-control page (frontend) showing per-round, per-team lock/advance status.
* Manual lock: instructor forces all unlocked teams to lock at current revision.
* Manual advance: existing endpoint wired to UI.
* Pause/resume instance: set status, reject student sheet patches while paused, resume.
* Reopen: instructor unlocks a locked-but-not-advanced team via existing service.
* Schedule visibility: read current round schedule with team-level timestamps.
* Round schedule settings editor (duration, auto-advance, grace period).
* Backend API tests and browser proof.

### Out of scope

* Scheduler tick automation / cron infrastructure.
* Student-facing schedule display.
* Grade/export integration.
* New database tables or migrations.
* Monitoring dashboard (separate M5.4 packet).
* Clone, archive, or reset workflows.

## Acceptance tests

The builder should add focused tests with these observable assertions.

1. **Pause enforcement:** instructor pauses an active instance → student `PATCH` to
   controls returns 409 with `instance_paused` error; instructor resumes → student
   `PATCH` succeeds again.
2. **Manual lock:** instructor locks round N; all draft teams become locked;
   already-locked teams unchanged; completed teams skipped.
3. **Manual advance:** instructor advances; all teams reach round N+1 or completed;
   instance status updates correctly.
4. **Reopen:** instructor reopens a locked-but-not-advanced team; team returns to
   draft with incremented revision; other teams unaffected.
5. **Schedule read:** response shows per-round `start_at`, `deadline`,
   `decisions_locked`, and per-team `locked_at`/`advanced_at`.
6. **Settings update:** instructor changes duration/grace/auto-advance; persisted in
   `instance.settings`; next round schedule reflects new values.
7. **Auth:** student cannot call any round-control route; instructor for another
   course gets 403.
8. **Browser proof:** instructor page shows round grid with team status,
   lock/advance/pause buttons.

The packet is complete only when the browser proof is observed.  API-only success
does not close the M5.3 gate.
