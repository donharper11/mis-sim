# M5.6 registry admin — casepack registration and management contract

Date: 2026-10-02
Status: bounded implementation handoff; no runtime implementation is included here.
Scope: admin-only HTTP registration, validation report viewing, and deregistration of on-disk casepacks.

## Decision

The M5.6 slice delivers an **admin-only casepack registry management surface**:
HTTP registration of on-disk packs, validation report retrieval, bound-instance
queries, and deregistration with binding protection.  It replaces the current
service-call-only registration workflow with a proper admin UI.

This is deliberately bounded to admin operations on already-deployed packs.  It does
not include file upload, remote pack fetch, content editing, validator changes, or
non-admin access to registration.

## Exact missing contracts

### 1. Admin registration route

New route:

```http
POST /api/admin/casepacks/register
```

Admin-only auth.  Request body:

```json
{
  "pack_key": "riverside_grocery",
  "pack_path": "backend/packs/riverside_grocery"
}
```

Calls the existing `register_casepack()` service.  Returns the `Casepack` metadata
plus validation summary:

```json
{
  "pack_key": "riverside_grocery",
  "pack_version": "0.1.0",
  "pack_digest": "<hex>",
  "display_name": "Riverside Grocery",
  "vertical": "grocery_retail",
  "schema_version": "1.0",
  "rounds": 6,
  "errors": 0,
  "warnings": 2,
  "exit_code": 0
}
```

Duplicate `(pack_key, pack_version)` registration returns 409.  Validation errors
do not prevent registration (existing behavior) but are flagged in the response.

### 2. Validation report route

New route:

```http
GET /api/admin/casepacks/{pack_key}/{pack_version}/validation
```

Admin-only.  Returns the full `validation_json` from the `Casepack` row:

```json
{
  "errors": [],
  "warnings": [
    {"code": "W001", "message": "Missing optional field", "location": "events/round_3.json:42"}
  ],
  "exit_code": 0
}
```

Returns 404 if the pack is not registered.

### 3. Bound instances query

New route:

```http
GET /api/admin/casepacks/{pack_key}/{pack_version}/instances
```

Admin-only.  Returns all `SimulationInstance` rows currently bound to this
`(pack_key, pack_version)`, with instance ID, section, course, and status.  This
informs the deregistration decision.

### 4. Deregister route

New route:

```http
DELETE /api/admin/casepacks/{pack_key}/{pack_version}
```

Admin-only.  Removes the `Casepack` registry row.  Returns 200 on success.
Returns 409 with bound instance IDs if any active instance is bound to this pack
version.  "Active" means instance status is not `'archived'`.

### 5. Registry list with validation status

The existing `GET /api/casepacks` response is augmented (or a parallel admin route
is added) with validation status indicators: error count, warning count, and a
boolean `is_valid` flag.

## Narrow packet boundary

### In scope

* Admin-only HTTP registration of on-disk packs.
* Validation report retrieval from persisted `validation_json`.
* Bound-instance query for a registered pack version.
* Deregistration with binding protection (409 if active instances bound).
* Registry list with validation status indicators.
* Admin-gated frontend page showing pack list, validation badges, and detail view.
* Backend API tests and browser proof.

### Out of scope

* File upload or remote pack fetch (packs are deployed to disk by ops).
* Pack content editing or authoring UI.
* Validator changes or new validation rules.
* Non-admin access to registration or deregistration.
* Pack versioning workflow or promotion.

## Acceptance tests

The builder should add focused tests with these observable assertions.

1. **Registration:** admin registers an on-disk pack; response contains `pack_key`,
   `pack_version`, `pack_digest`, and validation summary with zero errors.
2. **Duplicate rejection:** registering the same `(pack_key, pack_version)` twice
   returns 409.
3. **Invalid pack:** registering a directory with validation errors returns the
   registration with `errors > 0`; the pack is registered but flagged (existing
   behavior).
4. **Validation report:** `GET` returns the full finding list with codes, messages,
   and file locations.
5. **Bound instances:** detail response lists all instances currently bound to this
   pack version.
6. **Deregister success:** admin removes a pack version with zero bound instances;
   response 200; subsequent `GET /api/casepacks` omits it.
7. **Deregister blocked:** removing a pack bound to an active instance returns 409
   with the bound instance IDs.
8. **Auth:** instructor (non-admin) cannot register, deregister, or view the admin
   registry page; admin can.
9. **Browser proof:** admin opens registry page, sees pack list with validation
   badges, clicks a pack to see full findings, and the list refreshes after
   registration.

The packet is complete only when the browser proof is observed.  API-only success
does not close the M5.6 gate.

  `validation_json`; `GET /api/casepacks` metadata list; CLI validator; on-disk
  pack structure.
* **Must remain stable:** `Casepack` model fields; `register_casepack()` signature
  and behavior; pack directory layout under `backend/packs/`.
* **Consumed by M5.1/5.2:** instructor setup already uses pack selection from
  `GET /api/casepacks`; admin registration produces the rows that setup consumes.

  monitoring, or grading; it can proceed in parallel.
