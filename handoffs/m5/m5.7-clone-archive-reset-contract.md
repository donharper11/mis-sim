# M5.7 clone, archive, and reset — instance lifecycle contract

Date: 2026-10-02
Status: bounded implementation handoff; no runtime implementation is included here.
Scope: section clone, instance archive, and instance reset with confirmation tokens and state gating.

## Decision

The M5.7 slice delivers **clone, archive, and reset** lifecycle operations for
simulation instances.  Clone creates a new section with the same configuration but
no runtime state.  Archive marks a completed instance as read-only.  Reset destroys
all runtime state for a setup-status instance and returns it to round 0.

This is the final instructor-operations packet.  It deliberately excludes cross-course
clone, bulk operations, undo-archive, enrollment copy, and data export before reset
(the grade export route from M5.5 is the intended pre-reset workflow).

## New persistence (migration)

A single Alembic migration adds `'archived'` to the `SimulationInstance.status`
CHECK constraint:

```text
status: 'setup' | 'active' | 'paused' | 'completed' | 'archived'
```

No new tables are required.

## Exact missing contracts

### 1. Clone section

New route:

```http
POST /api/instructor/sections/{section_id}/clone
```

Instructor/admin-only; must own the section's course.  Creates a new section in the
same course with:

- Same `pack_key`, `pack_version`, and pack digest binding.
- Same team count and team names (new team IDs).
- Same instance `settings` JSON (round duration, auto-advance, grace period).
- New instance at `status='setup'`, `current_round=0`.
- No runtime state: no runs, sheets, checkpoints, results, or schedule rows.
- No enrollments: students re-enroll in the new section separately.

Returns the new section and instance summary.  The original section is unchanged.

Request body (optional):

```json
{
  "section_code": "B",
  "section_name": "Section B"
}
```

If omitted, defaults to the original section code/name with a `" (clone)"` suffix.

### 2. Archive instance

New route:

```http
POST /api/instructor/instances/{instance_id}/archive
```

Instructor/admin-only; must own the instance's course.  Request body:

```json
{
  "confirm_instance_id": 3
}
```

- Sets `instance.status = 'archived'`.
- Archived instances are excluded from instructor course setup list and monitoring
  list queries.
- Archived instances remain queryable for grade export (`GET .../grades` and
  `GET .../grades/export` from M5.5).
- Only `'completed'` instances can be archived; other statuses return 409.
- The `confirm_instance_id` must match the path `instance_id`; mismatch returns 422.

### 3. Reset instance

New route:

```http
POST /api/instructor/instances/{instance_id}/reset
```

Instructor/admin-only; must own the instance's course.  Request body:

```json
{
  "confirm_instance_id": 3
}
```

- Deletes all runtime rows for the instance: `SimulationRunV1`,
  `SimulationSheetV1`, `SimulationCheckpointV1`, `RoundResult`,
  `RoundSchedule`, `RoundScheduleTeam`, and any `grade_override`/`grade_config`
  rows from M5.5.
- Instance remains at `current_round=0` with the same pack binding, teams, and
  settings.
- Only `'setup'` instances can be reset; `'active'`, `'completed'`, or `'archived'`
  instances return 409 with an explanation (archive+clone or return to setup first).
- The `confirm_instance_id` must match; mismatch returns 422.
- Other instances in the same course are unaffected.

## Narrow packet boundary

### In scope

* Clone section with pack binding, team structure, and settings; no runtime state
  or enrollments.
* Archive a completed instance; exclude from setup/monitoring lists; preserve grade
  export access.
* Reset a setup-status instance; destroy all runtime state; preserve structure.
* Confirmation token on reset and archive to prevent accidental invocation.
* Status constraint migration adding `'archived'`.
* Frontend buttons on the instructor setup page with state gating.
* Backend API tests and browser proof.

### Out of scope

* Cross-course clone (clone to a different instructor's course).
* Bulk operations (clone/archive/reset multiple sections).
* Undo archive (archived is a terminal read-only state for v1).
* Data export before reset (instructor should use the M5.5 export route first).
* Enrollment copy (students re-enroll in the new section).
* Deletion of sections or courses.

## Acceptance tests

The builder should add focused tests with these observable assertions.

1. **Clone:** instructor clones section A; new section has same `pack_key`,
   `pack_version`, team count, and settings; new instance is at `status='setup'`,
   `current_round=0`; no runtime rows exist; original section is unchanged.
2. **Archive:** instructor archives a completed instance; status becomes `'archived'`;
   instance is excluded from setup list but included in grade export route.
3. **Archive rejected:** archiving a non-completed instance returns 409.
4. **Reset:** instructor resets a setup-status instance; all runtime tables for that
   instance are empty; instance remains at round 0 with the same pack binding.
5. **Reset rejected:** resetting an active or completed instance returns 409 with
   explanation.
6. **Confirmation:** reset/archive without the confirmation token returns 422.
7. **Cascade verification:** after reset, a `SELECT` on every runtime table for that
   `instance_id` returns zero rows; other instances are unaffected.
8. **Auth:** only the owning instructor or admin can clone/archive/reset; other
   instructors get 403; students get 403.
9. **Browser proof:** setup page shows clone/archive/reset actions with appropriate
   state gating (clone always available; archive only on completed; reset only on
   setup).

The packet is complete only when the browser proof is observed.  API-only success
does not close the M5.7 gate.
